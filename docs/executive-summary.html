When a future candidate is approved

Exact upload sequence

1

Check the separate slot selector

This audit page does not approve a weekly slot. Only a separate selector may decide to submit an explicitly labelled experiment; first inspect the exact artifact hash, holdout evaluator/version, withheld-positive count, 95% CI, registry comparison, and format receipt.

2

Download the named GeoTIFF

Save the exact linked .tif file. Do not resave, reproject, rename its contents, or substitute a ZIP from another run. If a ZIP is offered, confirm it contains a single GeoTIFF.

3

Open the official contest

Use the DrivenData competition page and choose the new-submission flow. Use the normal sign-in flow; this review did not access a submission portal or bypass authentication.

4

Attach the file

In “File to submit,” choose the downloaded single-band .tif (or the ZIP only if it contains one TIFF). Confirm the displayed filename matches the run card.

5

Enter the identifying fields

Paste the exact unique submission name and short note supplied for that raster. Do not copy a prior name or use a projected score in the note.

6

Submit and preserve the receipt

After portal validation, save the organizer's result/receipt and link it to the raster hash. Only that receipt can support an ORGANIZER-CONFIRMED score claim.

Troubleshooting

“Predicted values must be in range [0, 1]”

The message indicates that the submitted prediction values failed the portal's range check. Common causes include NaN/Inf cells, a nodata sentinel such as a very large negative value, negative values, or values above one. The message alone does not tell us which value or cell caused the rejection; without the rejected file, no single root cause can be asserted.

Run the local validator against the candidate and the cached label footprint (the local label raster is not organizer-authenticated):

python scripts/validate_submission.py path/to/candidate.tif \
  --labels data/grid/labels.tif --out evidence/candidate.validation.json

A passing local check confirms only local format/range conditions. It does not confirm the organizer accepted the file, the holdout is powered, or the candidate should use a weekly slot.

Rules

When is a file OK to submit?

All five conditions must hold. Until they do, the answer is no.

  1. The file has a HOLDOUT-DTI with evaluator version, withheld-positive count and 95 % CI.
  2. Its paired CIs against the matched random null and against the placebo both lie entirely above 0 (segment-group jackknife).
  3. The leakage canary is at most AUC 0.90 for every feature.
  4. The format validator passes (single band, float32, EPSG:32611, 100 m, same bounds, no NaN in the footprint, values in [0, 1]).
  5. The owner records a selection. Selection is a separate step from scoring; this page never selects a file.

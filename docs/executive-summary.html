Error fix

“Predicted values must be in range [0, 1]”: what we know and what to check

What is established. The error text is what the portal returns. We could not reproduce it offline, so we do not know which pixel triggered it. Our two candidate files contain only the values 0 and 1 inside the footprint and no NaN inside it (validator output). Across the 1,223 corpus rasters we read, 62 contain values outside [0,1]. All are input, label or intermediate layers, and none is a leaderboard prediction. Examples: uint8 probability maps (0–237), int16 maps (down to −32768), int8 labels (−1..1), SGMC u8 (nodata 255).

What is not established. The earlier claim that a float32 sentinel or a NaN nodata tag causes this error was not verified (IR-54-076). The corpus also contains NaN-tagged files with owner-reported board values (IR-54-079). The claim that the all-finite file was "already accepted" by the portal has no receipt (IR-54-072).

Likeliest cause (hypothesis). An intermediate or input raster was uploaded in place of a prediction. This matches the out-of-range layers above.

Checklist before any upload.

  1. Dtype float32, single band, EPSG:32611, 3,730 × 3,292, transform (100, 0, 243350, 0, −100, 4508550).
  2. Inside the footprint: finite, values in [0,1]; dots = 1, background = 0.
  3. Outside the footprint: NaN (the organizer page). The organizer's reference notebook writes all-finite zeros. The two conflict, so confirm the portal's rule before a slot.
  4. No sentinel anywhere (−1, 255, −32768, −3.4028e+38). Check the nodata tag and every cell.
  5. Run scripts/validate_submission.py; it must pass.

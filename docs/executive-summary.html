What the numbers mean. Dense 1-px ridge lines add redundant dots that the pooled DTI does not credit, so they lose to random placement. The spaced variant ties the null. Rules

When is a file OK to submit?

All five conditions must hold. Until they do, the answer is no.

  1. The file has a HOLDOUT-DTI with evaluator version, withheld-positive count and 95 % CI.
  2. Its paired CIs against the matched random null and against the placebo both lie entirely above 0 (segment-group jackknife).
  3. The leakage canary is at most AUC 0.90 for every feature.
  4. The format validator passes (single band, float32, EPSG:32611, 100 m, same bounds, no NaN in the footprint, values in [0, 1]).
  5. The owner records a selection. Selection is a separate step from scoring; this page never selects a file.
When a file is approved

Exact upload sequence

1

Check the run card

The file's run card must show ok_to_submit: true. The current card in docs/data/run-card.json shows false.

2

Download and check the hash

Confirm the SHA-256 matches the run card. If it differs, do not upload.

3

Sign in to DrivenData

Open the competition problem page for the submission format. The data page requires a login (verified: it redirects to login). No credential is stored here.

4

Attach one GeoTIFF

Upload a single-band .tif directly. Use a ZIP only if the form asks for one and it contains one TIFF.

5

Note (max 140 characters)

Use the note from the approved run card. The note for this prior file (105 characters) is GEMSDOE54 undercomplement-q200: SGMC state-map complement of catalogue, d>300m, linearity gate, 200m dots. It applies only if this file is approved.

6

Submit and keep the receipt

Only a number copied from the submission page is ORGANIZER-CONFIRMED. Record it in registry/submissions.json with the raster hash.

Before upload, run the local validator. This does not guarantee portal acceptance:

python scripts/validate_submission.py docs/downloads/gems54-undercomplement-q200.tif --labels data/grid/labels.tif --out evidence/candidate.validation.json
The "[0, 1]" error

"Predicted values must be in range [0, 1]"

A user reported this message from the portal. The repository holds no receipt of that upload, so the cause is not established. Typical causes are NaN or Inf values, a nodata sentinel such as a large negative number, or values outside [0, 1]. This file has only the values 0 and 1 and no NaN, and the local validator checks for those conditions.

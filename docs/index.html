The problem, in four sentences

The competition asks for a fault-probability GeoTIFF over the GeoDAWN study area in western Nevada. Scoring uses a distance-weighted Tversky index with α = 0.2 (false positives), β = 0.8 (false negatives) and a triangular 300 m kernel, and — crucially — the ground truth is only the faults that are missing from the public catalogue, which geology experts at NLR and USGS identified by hand. Every cell you mark pays a small linear false-positive tax, while every truth cell you miss costs four times as much, so the achievable score is set by how precisely you can place a small number of confident predictions. A prior repository record lists 0.3774 and 0.2778 as board observations, but this audit pass has no submission-page receipts; they are not ORGANIZER-CONFIRMED scores and are not used to select a target or weekly slot.

How to submit — step by step

Verified against the competition problem description (submission format) and the DOE/NLR Official Rules, §3.2 (three submissions per week).

  1. Download the file. Use the green button above. The download is the exact artefact whose SHA-256 is printed beside it; if your copy's hash differs, do not upload it.
  2. Register / sign in on DrivenData and open the GEMS challenge, then the Submissions tab. (Registration is required by the rules and is also how the feature data is obtained — see Limitations.)
  3. Click New submission. The form accepts a single-band GeoTIFF (.tif), or a .zip containing one. Upload gems54-undercomplement-q200.tif directly — do not zip or re-encode it.
  4. Optionally paste the 105-character note from the green panel above into the Note field. This is the field the form describes as "a short comment to help you or your team tell submissions apart later".
  5. Click Submit. The portal re-checks CRS, shape, geotransform and the value range. The prior local validator receipt records all four format checks as passing for this file; that does not establish portal acceptance, a competition score, or performance validity.
  6. Record the receipt. If it scores, copy the number into registry/submissions.json as ORGANIZER-CONFIRMED. Until then it stays unscored.

Why the earlier upload failed. The portal's message "Predicted values must be in range [0, 1]" is raised when the raster it reads contains a value outside [0, 1] — most often a nodata sentinel such as -1, 255 or -32768 that the reader does not mask, or a NaN that the validator treats as a number. This repository therefore emits no nodata tag and no NaN at all: the array is finite everywhere and every value is exactly 0.0 or 1.0. scripts/validate_submission.py re-reads the written file from disk and asserts min >= 0, max <= 1 and non_finite == 0 before the file is allowed to be published.

What this artefact is

A unit-valued dot set, not a probability field. Dots are placed on USGS State Geologic Map Compilation faults that lie more than 300 m from the competition catalogue, filtered to trace-like shapes, and thinned so that no two dots are closer than 200 m. The rationale, the algebra and the falsifiable prediction are on the Evidence page.

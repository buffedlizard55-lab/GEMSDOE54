Can the holdout detect the 0.2778 vs 0.2750 gap?

E3 (detection_floor.json) measured the jackknife standard error of paired differences. Pair A−B (two near-identical quantile thresholds) has an 80 %-power floor of 0.0022; pair A−C (dense vs spaced) has 0.0015. So a 0.0028 gap could be detected on this holdout for near-identical variants. This does not settle the board question: the board values use a hidden truth set and a different scorer, and the variance of those comparisons is unknown. The board gap is NOT CLASSIFIABLE.

How to submit — only after a candidate clears the gates

This is a general portal checklist, not an approval to submit the archived file. The submission format/rules links below were supplied by the user and should be checked on the live competition pages before an upload.

  1. Use only a selected, validated candidate. This review has none. Do not upload the archived H54-A file linked above. A future candidate must have a compliant whole-segment HOLDOUT-DTI, paired 95% CI, leakage-canary results, literal lane pass, and a format-validation receipt.
  2. Download that candidate's exact GeoTIFF from its run card. Verify the SHA-256 against the receipt; do not re-encode it or substitute an archive.
  3. Sign in to DrivenData and open the GEMS challenge's submissions page. The competition data tab and submissions flow may require an account; this repository cannot authenticate or submit on the user's behalf.
  4. Choose New submission. The user-supplied form text says the accepted file is a single-band GeoTIFF (.tif), or a .zip containing one GeoTIFF, matching the submission CRS, shape, and geotransform. Confirm the current instructions on the live page.
  5. Enter the unique experiment name and short note from the validated run card (maximum 140 characters under this project's requested limit). There is no new candidate-specific note from this review.
  6. Check the current weekly cap before submitting. Click Submit only after the separate selector has approved a real slot. Copy the portal receipt and exact score into registry/submissions.json; do not infer a score from a local projection or sibling-site record.

Interpreting the earlier range error. The portal message says some value it parsed was outside [0, 1]. Without the exact original upload bytes and its receipt, the cause cannot be determined. Typical issues to check include finite-value handling, nodata sentinels, and values outside the allowed range. The local validator re-reads a candidate and checks those properties, but a local pass is not proof of portal acceptance.

Executive summary · submit guide · DOE GEMS Prize (DrivenData competition 306)

Four GeoTIFFs are in the repository. None is cleared for upload, and the download status of one is in conflict.

Download conflict: registry/submissions.json marks the CGRC relay file (gems54-cgrc-relay-v1.tif, from a parallel 2026-10-09 session) as “OK TO DOWNLOAD”, while the 2026-10-09 README section says not to download any file. The repository does not resolve this. Treat it as not cleared until the owner decides. See the README status block and the CGRC run page. The rules allow you to submit your own model's output. No file meets your uniqueness requirement under the literal lane rule. The best holdout file (H54-A) is not unique. The newest file (H1, cross-gradient) fails the holdout gate and its lane verdict is disputed. Under the protocol, no slot is recommended. Choosing a slot is your decision.

3. If you decide to submit anyway, do this exactly

These steps are the rules' steps, plus the checks this repository runs. They do not override the uniqueness finding.

  1. 1 Register on DrivenData, join the competition, and accept its rules (§3.1). Competition page: drivendata.org/…/competition-doe-gems. End date: Dec. 3, 2026, 11:59 p.m. UTC.
  2. Confirm eligibility under §1.3 and be ready to sign the certification in §1.3 and A.1. Only you can do this.
  3. Download the file and check its hash: sha256sum gems54-undercomplement-q200.tif must print b430615a…efd8 for H54-A, 6d086c09…8d9e for H54-B, or 006e912b…f26d05 for H1.
  4. Validate the format: python scripts/validate_submission.py <file> --out check.json. Format checks must all pass.
  5. Note (≤140 characters). H54-A: GEMSDOE54 undercomplement-q200: SGMC state-map complement of catalogue, d>300m, linearity gate, 200m dots (105 characters). H54-B: GEMSDOE54 magedge-hgrad-ridge: tmi_hg magnetic gradient ridges, >300m from catalogue, linearity gate, 200m dots (111 characters).
  6. Upload one GeoTIFF on the submission page. Format (DrivenData, format section): EPSG:32611, 100 m, same bounds, float32, single layer, values in [0, 1], NaN or null outside the bounds. Format note: all three shipped files store 0 outside the footprint, not NaN. The page says NaN or null, and the strict check here fails for every file. The “Predicted values must be in range [0, 1]” error has not been reproduced from any repository file. Ask the organizers before uploading (IR-54-053, IR-54-054).
  7. Narrative: include the generative-AI disclosure from AI_DISCLOSURE.md (§3.2).
  8. Limits: at most three submissions per week (§3.2, §3.4), and one final submission selected before the deadline (§3.4).
  9. Finalists: supply complete code and documentation (§3.5). The builder, the receipts, and the holdout evaluator are in this repository.

Rule questions go to the organizers, not to this repository. Email gemsprize@nlr.gov or ask on the competition forum. The homepage gives both channels. Ask specifically about the training-label source (IR-54-030) and about the sample submission (IR-54-032).

4. What would make a file upload-ready

  • A new lane. The SGMC-complement lane is taken (sibling sgmc-gap submissions) and the magnetic-edge lane is crowded (GEMSDOE40, GEMSDOE46). A candidate needs dot placement that is not a near-copy of a sibling's dots. This session did not find one that is also validated.
  • A holdout that beats the best. Any new file must beat H54-A's holdout (0.0483) under the same evaluator, with non-overlapping CIs. In this session the holdout scored four candidates (C1 SGMC complement, C2 geodetic shear, C3 magnetic gradient, C4 cross-gradient, which is H1) and a fifth, C5 basement-step, which is not a file. The C4 and C5 holdout runs were the last two of the three-experiment budget. None beats H54-A, and C5 is at the chance control (0.0103 [0.0076, 0.0133]).
  • Organizer confirmation of label source and sample format (IR-54-030, IR-54-032), and a check of the submission count (IR-54-040).
